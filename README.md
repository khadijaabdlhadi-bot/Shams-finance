# المنظومة المالية — مدرسة شمس الوطن

**نظام مالي وإداري كامل** لإدارة رسوم الطلاب: طلاب، أرقام وطنية، رسوم، دفعات، إيصالات،
تقارير، سجل عمليات، نسخ احتياطي واسترجاع — يعمل على **شبكة المدرسة المحلية بدون إنترنت**،
وقابل للنقل إلى أي كمبيوتر آخر بدون ضياع بيانات.

```
┌──────────── شبكة المدرسة ────────────┐
│  المحاسبة    الإدارة     لابتوب المدير │
│     └──────────┼──────────┘            │
│           http://192.168.x.x:8080      │
│        ┌───────▼────────┐              │
│        │ الجهاز الرئيسي  │              │
│        │ التطبيق + قاعدة │  ← نسخة واحدة مركزية
│        │ البيانات        │     يراها الجميع
│        └────────────────┘              │
└────────────────────────────────────────┘
```

## التشغيل السريع

```bash
cp .env.example .env      # ثم غيّر كلمات المرور بداخله
docker compose up -d      # التطبيق + قاعدة البيانات
```

افتح `http://localhost:8080` ← `admin` / كلمة المرور من `ADMIN_PASSWORD`.
من بقية الأجهزة: `http://عنوان-الجهاز:8080`.

الدليل الكامل خطوة بخطوة في **[INSTALLATION.md](INSTALLATION.md)**.

بدون Docker:

```bash
npm run setup && npm run build && npm start
```

### أوامر مفيدة

```bash
npm run seed:demo              # 24 طالبًا تجريبيًا مع رسوم ودفعات — للتدريب قبل الإدخال الحقيقي
npm run seed:demo -- --clear   # حذف البيانات التجريبية وحدها (أرقامها الوطنية تبدأ بـ 9999)
npm run backup                 # نسخة احتياطية من سطر الأوامر (للجدولة في Task Scheduler)
npm run backup -- --list       # عرض النسخ الموجودة
npm run backup -- --verify     # عدّادات التحقق الحالية
npm run create-admin           # إنشاء مدير أو إعادة ضبط كلمة مروره
```

## ما الذي يقدّمه النظام؟

| المجال | التفاصيل |
|---|---|
| **الطلاب** | رقم وطني فريد (نص، بأصفاره)، رقم طالب تلقائي `STU-2026-000001`، أولياء أمور، صفوف وفصول، سنوات دراسية، أرشفة بدل الحذف |
| **الرسوم** | دراسية · تسجيل · زي (اختياري لكل طالب) · إضافية · خصومات بسبب ومنفّذ، وسجل لكل تعديل |
| **الدفعات** | تسجيل بمعاملة واحدة، توزيع على البنود، طرق دفع قابلة للتوسعة، إلغاء بسبب (بلا حذف) |
| **الإيصالات** | رقم فريد `SHW-2026-000001`، لقطة كاملة وقت الدفع، طباعة عربية RTL، PDF، إعادة طباعة مسجّلة |
| **الأقساط** | لكل قسط: القيمة · المدفوع · المتبقي · شريط تقدّم · حالة تلقائية (مدفوع/جزئي/متأخر)، ودفعات مستقلة بإيصال لكل دفعة، وتعديل محمي لا يسمح بخفض القيمة تحت المدفوع |
| **القسم المالي** | لوحة المالية · الطلبة والمدفوعات · الأقساط · الخزينة · ديون الطلبة · الخصومات · طرق الدفع · التقارير |
| **الخزينة** | رصيد فعلي، مقبوضات اليوم والشهر حسب الطريقة والموظف، وحركة لكل دفعة (وارد) وكل إلغاء (عكسي) |
| **Excel** | **زران منفصلان**: تحميل نموذج فارغ للإضافة · وتصدير الطلاب الحاليين من قاعدة البيانات (كل الطلاب أو النتائج المفلترة) بالأرقام المالية وحالة الدفع، مع ورقة ثانية للأقساط |
| **التقارير** | 6 تقارير مع فلاتر، وتصدير Excel و PDF وطباعة تحترم نفس الفلاتر |
| **سجل العمليات** | من فعل ماذا ومتى، مع القيم القديمة والجديدة وعنوان IP |
| **الصلاحيات** | 3 أدوار جاهزة و21 صلاحية، والتحقق في الخادم لا في الواجهة |
| **الحسابات وكلمات المرور** | صفحة «حسابي»: كل مستخدم يغيّر **اسم المستخدم وكلمة المرور** بنفسه (بتأكيد كلمة مروره الحالية)، والمدير يعيّنها لأي موظف، وإجبار على التغيير عند أول دخول بكلمة عيّنها غيرك |
| **النسخ الاحتياطي** | يدوي ومجدول، بصمة SHA-256، عدّادات تحقق، واسترجاع آمن بفحص قبلي وبعدي |
| **نقل النظام** | زر واحد «تجهيز ملف النقل» ينقل كل شيء لجهاز آخر — بما فيه **عدّادات الترقيم** فلا يتكرر رقم إيصال |

## سلامة الأرقام — كيف نضمنها

- كل المبالغ `NUMERIC(14,2)` في قاعدة البيانات، وتُحسب في الخادم بوحدات صغرى **صحيحة**.
  لا `FLOAT` في أي مكان، فلا وجود لخطأ `0.1 + 0.2 = 0.30000000000000004`.
- **لا نخزّن** المستحق ولا المدفوع ولا المتبقي. تُحسب من الرسوم والدفعات عند كل عرض،
  فلا يمكن أن «تنحرف» عن الحقيقة.
- تسجيل الدفعة كله داخل **معاملة واحدة** مع **قفل صف الطالب**؛ موظفان في نفس اللحظة يصطفّان
  بدل أن يقرأ أحدهما رصيدًا قديمًا. أي فشل ⇒ لا دفعة ولا إيصال ولا رصيد نصف محدَّث.
- الرقم الوطني ورقم الإيصال محميّان بقيود `UNIQUE` **في قاعدة البيانات نفسها**، لا في الكود فقط.
- التوقيت من ساعة الخادم دائمًا، لا من جهاز الموظف.
- الواجهة تعرض فقط — **الخادم هو المرجع النهائي لكل حساب**.

## الأمان

كلمات المرور بـ bcrypt · تحديد محاولات الدخول وقفل مؤقت · استعلامات Parameterized (لا حقن SQL) ·
React يمنع XSS · لا Cookies للمصادقة ⇒ لا CSRF · صلاحيات على الخادم · رسائل خطأ عربية بلا تفاصيل
تقنية · قاعدة البيانات غير منشورة على الشبكة · الأسرار في `.env` خارج المستودع.

## معلومات الدخول الأولى

| الحساب | الاستخدام |
|---|---|
| `admin` + `ADMIN_PASSWORD` من `.env` | مدير النظام — كل الصلاحيات |

أنشئ بعدها حسابات الموظفين من **المستخدمون والصلاحيات**:
**محاسب** (طلاب ودفعات وإيصالات وتقارير) · **إدخال بيانات** (إضافة الطلاب و Excel فقط).

> غيّر كلمة مرور المدير فور أول دخول من صفحة **حسابي**، وغيّر `JWT_SECRET` و`DB_PASSWORD` قبل الاستخدام الفعلي.

### كلمات المرور وأسماء المستخدمين

- **حسابي** (من الشريط العلوي): يغيّر المستخدم كلمة مروره أو اسم مستخدمه بنفسه، ويلزمه
  إدخال كلمة مروره الحالية في الحالتين. الجلسة تستمر بلا انقطاع بعد التغيير.
- **المستخدمون والصلاحيات** (للمدير): تعيين كلمة مرور جديدة أو تغيير اسم مستخدم أي موظف.
- من يعيّن له المدير كلمة مرور **يُطالَب بتغييرها فور أول دخول** قبل استخدام النظام.
- الحساب يُقفل مؤقتًا بعد 6 محاولات خاطئة، وكلمات المرور مخزّنة بـ bcrypt ولا تظهر في أي سجل.
